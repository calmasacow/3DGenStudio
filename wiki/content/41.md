# Bake

Capture a high-poly mesh's detail onto the current mesh's UVs as textures — a normal map, ambient occlusion, base colour and the PBR channels. Baking runs headless **Blender** on the Python mesh-tools service.

Bake is what makes **[Auto Retopo](30.md)** and **[Optimize / LOD](31.md)** non-destructive. On their own those tools hand back clean topology with the detail *deleted*; baking puts that detail back as a texture, so a 6,000-face mesh still reads as the 300,000-face one it came from.

> Bake runs on the **Python mesh-tools service**. Make sure it is configured and running in **Settings → Mesh Tools** before using this mode. In the desktop app the service is started for you.

## Before you start

Two things must be in place:

- **The current mesh needs UVs.** They are where the maps get written; without them there is nowhere to bake to. The panel says so and the Run button stays disabled — run **[Auto UV](29.md)** first.
- **You need a high-poly source.** See below.

## The high-poly source

The source is the mesh whose detail is captured. There are two ways to get one:

**Automatic snapshots.** The editor keeps the mesh from *just before* every tool run — Auto Retopo, Optimize, applying a LOD, Auto UV, and so on — as a bake source. That is the only moment the detail still exists, so it's captured for every tool rather than a chosen few. Entries are listed newest first and labelled with the tool, the face count and the time (e.g. *Before Auto Retopo · 312,480 faces · 14:22*), because several runs of the same tool would otherwise look identical. Up to **10** snapshots are kept — each one is a full mesh held in memory, so it's a cap rather than a full history.

Snapshots include the texture when the mesh has one, so a base-colour transfer reproduces the actual artwork rather than a flat placeholder.

**A library asset.** Click **Choose a mesh asset…** to pull any mesh from the asset library in as the source. Versions are selectable too, which is the common case: the high-poly is usually an earlier version of the very mesh you're editing.

## Running it

1. Open the **Bake** mode in the left toolbar.
2. Pick the **High-poly source**.
3. Tick the **Maps** you want and set the **Quality** options.
4. Click **Run Bake**. Progress is reported per pass.
5. Inspect the resulting maps in the **Result** section, then click **Apply to mesh**.

A typical clean-up pass looks like: generate or import a heavy mesh → **Auto Retopo** (snapshot captured automatically) → **Auto UV** on the light result → **Bake** with the *Before Auto Retopo* source selected → **Apply to mesh**.

## Maps

| Map | What it carries |
| --- | --- |
| **Normal (tangent space)** | The silhouette and surface detail lost when the mesh was simplified. This is the map that does most of the work. |
| **Ambient occlusion** | Contact shadow in creases and cavities. The only pass noisy enough to need a meaningful sample count. |
| **Base colour (albedo)** | Transfers the source's texture onto the new UV layout — this is what gives a retopologised mesh its artwork back. |
| **Roughness** | Resamples the source's roughness channel onto the new UVs. |
| **Metallic** | Resamples the source's metallic channel onto the new UVs. |

Normal and AO are selected by default.

When two or more of **AO / roughness / metallic** are baked, the service also returns them packed into a single R/G/B **ORM** texture — the layout glTF expects — and that packed texture is what gets applied and exported.

> If a channel comes from a *constant* on the source material rather than a texture, the bake result says so and the map comes back flat. The material's own value is better than a flat texture, so leave those unchecked.

## Quality

| Field | Default | What it does & how to tune it |
| --- | --- | --- |
| **Resolution** | 2048 | Output map size (512 / 1024 / 2048 / 4096). Cost scales with the **square** of this — a 4096px AO bake against a dense source can take minutes. Match it to how close the asset will be seen. |
| **Samples** | 8 | Cycles samples per pixel. Only the AO pass is noisy enough to need more than a few; **raise it** if AO looks grainy, **lower it** for speed when you're only baking normals. |
| **Cage extrusion** | 0 (automatic) | How far outside the surface the rays start, in metres. **Too small** misses detail that sticks out (the ray starts inside the high-poly and records nothing); **too large** catches surfaces from the other side of the mesh, which shows up as ghosting. **0 scales it to the mesh** — 2% of its bounding-box diagonal — which is right far more often than any fixed distance. Only set it by hand when the automatic value visibly misses or ghosts. |
| **Margin (texels)** | 8 | Dilates the baked islands outwards into the gutter, so texture filtering and mip-mapping cannot sample empty space and bleed seam lines across the surface. **Raise it** if you see seams at a distance; it costs nothing but atlas space. |

## Applying the result

**Apply to mesh** puts each baked map where it belongs:

- **Normal** attaches to the material as its normal map.
- **AO, roughness and metallic** attach as the single packed **ORM** texture (or individually, when fewer than two of them were baked).
- **Base colour** is drawn into the paint texture — which *is* the editor's base colour, so it immediately becomes paintable and projectable like any other texture.

All of them then travel with the mesh when you save and when you export.

---

Baking is read-only towards the geometry: nothing about the mesh changes, so there is no Keep/Revert here. Only **Apply to mesh** touches the asset, and its texture changes are saved with the mesh like any other edit.
