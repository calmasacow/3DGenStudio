# Optimize / LOD

Reduce the triangle count of your mesh while preserving its shape. Optimize runs the bundled **gltfpack** (meshoptimizer) binary to simplify the geometry — either once at a ratio you choose, or as a whole **LOD chain** — which is how you produce lighter versions for real-time use or export.

> Unlike Auto UV and Auto Retopo, Optimize does **not** require the Python mesh-tools service. It uses the gltfpack binary shipped with the app.

## Running it

1. Open the **Optimize** mode in the left toolbar.
2. Set the **Simplify ratio** to the fraction of triangles you want to keep.
3. Click **Run Optimize** and wait for it to finish.
4. The result replaces the current mesh and reports the applied ratio. Click **Keep** to accept it, or **Revert** to restore the previous mesh.

Optimize preserves the existing UV layout — it only removes geometry, so any texturing you've already done stays intact.

> The mesh from *just before* the run is kept automatically as a high-poly **[Bake](41.md)** source. That is what makes Optimize non-destructive: simplify first, then bake the detail you removed back onto the lighter mesh as a normal map.

## Parameters

### Simplify

| Field | Default | What it does & how to tune it |
| --- | --- | --- |
| **Simplify ratio** | 0.5 | Target triangle count as a fraction of the original (1 = no simplification, 0.5 = roughly half the faces). |
| **Allow UV seams to break** | Off | Lets the simplifier weld UV seams to reach the target (see below). **Leave it off** for anything textured; **turn it on** only when the mesh is untextured or you intend to re-bake it. |

When the current mesh has a known face count, the panel shows a live estimate:

- **Current faces** — the mesh's face count before optimizing.
- **Target faces** — the approximate count after optimizing (`current faces × simplify ratio`).

For example, with a 100,000-face mesh and a ratio of `0.1`, the target is roughly ~10,000 faces.

## The UV-seam floor

The simplifier cannot collapse an edge that crosses a UV seam without welding that seam, and welding it moves the texture. So on a heavily-seamed mesh — which is what most generated and auto-unwrapped assets are — simplification hits a **floor**: it stops well short of your target and reports the ratio it actually reached rather than the one you asked for.

That is deliberate. Under-simplifying and saying so beats silently ruining the asset.

Two ways past it:

- **Enable *Allow UV seams to break*.** The target is reached, but the texture will be distorted on any mesh that needs it. The panel warns while the toggle is on, and any LOD level that welded seams is flagged afterwards.
- **Re-unwrap or re-bake.** Simplify hard with seams broken, run **[Auto UV](29.md)** on the result, then **[Bake](41.md)** the original detail (and base colour) onto the new UVs. This is the clean route for a real game asset.

## LOD chain

A LOD (level of detail) chain is the same mesh at several triangle budgets, so an engine can swap to a cheaper version as the camera pulls away. The panel builds every level in one pass and reports the **real** triangle count of each, so you can judge the ladder before committing to it.

| Field | Default | What it does |
| --- | --- | --- |
| **Levels** | 4 | How many levels to build (2–6). **LOD0** is the mesh as it stands; each level after it roughly halves the triangle count — the same ratios Unity's and Unreal's own auto-LOD tools default to. |

The **Ratios** line shows what will be requested, e.g. `100% / 50% / 25% / 13%` for 4 levels.

1. Click **Generate LOD chain**. Every level is built server-side and listed with the ratio it *achieved* and its triangle count.
2. Click **Apply** on any level to swap the viewport mesh for it, so you can judge the silhouette at real density. This behaves exactly like Optimize does — it's an undo step with the same **Keep** / **Revert** banner.
3. Click **Restore** on LOD0 to bring back the mesh the chain was built from. The level currently in the viewport is labelled **current** instead of Apply.

Notes:

- A ⚠ next to a count means that level **stopped early to protect the UVs** — the seam floor described above. A separate warning appears when levels *welded* seams to hit their target, in which case check the texture on those levels.
- **Rigged meshes keep their rig.** Skin weights are carried through simplification, so an applied LOD is still rigged and animatable.
- The chain is built from one snapshot of the mesh. If you edit the mesh afterwards, the panel says so (*"Built from a 120,000-face mesh; the current one has …"*) rather than showing figures that quietly stopped being true — regenerate to match.
- Applying a level only changes the mesh **in the editor**. To write every level to disk as `name_LOD0`, `name_LOD1`, … use the export dialog's **Generate LOD chain** option — see **[Mesh export](38.md)**.
